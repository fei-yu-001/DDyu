## 一、项目定位

把 `grok2api`（多账号 Grok API 网关）裁剪成一个**自用个人站的核心能力**，最终部署到 `ddyu.online`。

**只保留四件事：**

| 能力 | 上游渠道 | 账号数 |
|---|---|---|
| 对话（Responses / ChatCompletions / Messages） | `grok_build` | 194 |
| 生图 `/v1/images/generations` | `grok_web` | 52 |
| 图编 `/v1/images/edits` | `grok_web` | 52 |
| 文生视频 `/v1/videos/generations` | `grok_web` | 52 |
| **账号凭证刷新**（Build OAuth 定时刷新 + 轮换 + 退避） | — | — |

**明确剥离**：Grok Console 渠道、全部语音（TTS/STT/Realtime）、图生视频、视频编辑/延长、用户注册审批体系（用户自己后续开发）。

**站点形态**：`ddyu.online` 首页 = 博客（后续自建），创意工坊在 `/studio`。

## 二、关键决策（已定，不要推翻）

### 1. 技术栈不换

| 层 | 选择 | 理由 |
|---|---|---|
| 后端 | **Go（保留）** | 私有协议（WebSocket `/ws/mgw`、`/ws/imagine/listen`）+ 全套出口代理 + Cloudflare clearance + 账号调度，换栈等于月级重写 |
| 数据库 | **SQLite**（`glebarez/sqlite`，纯 Go 无 CGO） | 3-4 人使用，零配置，单机最合适 |
| 前端 | **React 19 + Vite 8 + TS 6 + Tailwind 4 + shadcn** | State of JS 2025：React 使用率 83.6%（第一），Vite 满意度 98%；且 2018 行创意工坊现成代码 |
| 部署 | **单二进制 + systemd + Cloudflare Tunnel** | 免公网 IP、自动 HTTPS、复用已有 Cloudflare |

**否决过**：Vue（与 cloud-mail 不共享代码，统一收益为 0）、Svelte（Svelte 5 范式级变化）、Next.js/Nuxt（引入 Node 运行时，破坏单二进制）、Astro（官方定位不适合重度交互 SPA）。

> 博客将来若要做 SEO，可**单独**用 Astro 静态站，与 React SPA 并列，同域名不同路径。**不要**为迁就博客换掉 React。

### 2. 与 cloud-mail 的关系

`fei-yu-001/cloud-mail` 是 Cloudflare Workers + Hono + D1/KV/R2 的**纯 Serverless** 应用。
**两者技术栈不应统一**——Cloudflare Workers 官方明确无法指定出站 IP，且禁止连接私有网络，与本项目「账号 ↔ 固定出口 IP」的基石直接冲突。
**只在域名/入口/运维层面统一**，代码各自独立。

### 3. 域名解耦（已核实）

换域名只需改 Nginx/Cloudflare 的 `server_name`，代码零改动：

- 前端所有请求都是**相对路径**（`/v1/...`、`/api/admin/v1/...`）
- 认证 Cookie `domain` 参数为空 → **host-only cookie**，不绑域名
- 后端媒体 URL 返回相对路径
- **唯一涉域名的配置项**是 `frontend.publicApiBaseURL` → **保持留空**

## 六、必须在后续注意的坑

### 1. 不能并行跑两个实例 ⚠️

本机 **`grok2api-lab` 容器当前正在运行**（healthy）。Build 的 refresh token 会**轮换**，两个实例同时用同一份凭据会互相消费掉对方的 token。
**启动新实例前必须先停掉旧容器。**

### 2. 媒体容量策略只能走运行设置

`media.local.maxTotalBytes` / `cleanupThresholdPercent` 等字段是 `yaml:"-"`，**不在配置文件里**，只能用数据库 `runtime_settings` 修改。
默认值 `maxTotalBytes: 1 GiB` + `cleanupThresholdPercent: 80` → **到 800MB 就会删你最早的作品**。
作品保留策略要在 API 层调整，**不能改 YAML**。

### 3. 生图有两个不能删的硬依赖

- `application/media/*` + `infra/media/*` —— `web/image.go:1475`，`assets == nil` 直接返回 `MediaPostProcessingError`，**不是降级**
- `application/audit/*` —— 绑着客户端**计费结算**（`application.go:337-338`），看着像日志其实是核心链路

### 4. quality-guard 不能砍

它是保护 Build 账号不被烧的核心（`gateway/selector.go:1150`：首次命中冷却 12h，冷却期内再命中 = **永久禁用**）。砍了会退回「每次请求烧 2.5 个账号」。
**只删 Python sidecar（`tools/egress-quality-guard/`）即可，进程内重试逻辑必须留。**

### 5. Web 渠道的三个前置条件

生图/视频要**同时**过三道关，任一条不通整条链路失败：

1. **Statsig 签名** `provider.web.statsigSignerURL`（默认 `https://grok.wodf.de/sign`）
2. **Cloudflare clearance**（`clearanceMode` + `flareSolverrURL`；`manual` 模式完全依赖导入时的 `cloudflare_cookies`）
3. **出口节点**（需为 `ScopeWeb` / `ScopeWebAsset` 配置代理）

> 生图走 WebSocket `/ws/imagine/listen`，视频走 `/rest/app-chat/conversations/new`，都在 CF 之后。

### 6. Cloudflare 反代的长连接

CF 对长时间无数据的连接有约 **100 秒空闲超时**。项目自带 25s 心跳，问题不大，但**必须实测 SSE 流式响应**。

### 7. 家宽上行带宽才是真瓶颈

246 个账号的流量全部从家里宽带上行出去。家庭宽带上行通常 30–100 Mbps，**比机器性能重要得多**。

### 8. 作品读取鉴权（P3 已修复，原「无鉴权」表述已过期）

**2026-09-11 P3 已修复**，原「任何人拿到 asset id 就能看你的作品」不再成立。

现状：读取端点为 `/v1/media/images/:assetId`、`/v1/media/videos/:assetId`，走
`mediaHandler.RegisterRead(router, middleware.MediaReadAuth(...))`（`server.go:152`）；
鉴权三条路径为 **管理员会话 OR 短期签名 URL（`?mexp=&msig=`）OR 客户端密钥**，归属不符一律 **404**（不泄漏存在性）。
`RegisterPublic`（`server.go:151`）**只剩一个上游回调端点** `/v1/media/uploads/:token` —— xAI 无法携带客户端密钥，票据本身即授权。

新增页面取作品必须走 `features/media/media-api.ts:mediaReadURL`，**不要自己拼 URL**（会丢签名参数导致 401，见第六节-11）。

### 9. 启动必须注入 `GROK2API_QUALITY_GUARD_DIR`

`qualityguard.Prepare`（`infra/qualityguard/bootstrap.go:58-65`）在 `qualityGuard.enabled=true` 时要求该路径非空，
否则启动直接失败：`qualityGuard 已启用，但未配置内部 bootstrap 文件路径`。
容器部署靠 `docker-compose.yml` 注入；**P7 的 systemd unit 必须同样注入**（本机直跑建议指向 `data/quality-guard`）。

### 11. 作品读取认「短期签名 URL」，别指望管理员 Cookie ⚠️

管理员 access Cookie 的 path 收敛在 `/api/admin/v1`（`transport/http/adminsession/cookies.go`），
浏览器同源 `<img>/<video>` **不会**携带它；而媒体标签也无法自定义请求头。
因此作品读取走「管理员会话 OR **短期签名 URL** OR 客户端密钥」三选一（见 P3 节）。
新增页面若用 asset id 自己拼 `/v1/media/...`，会丢掉 `?mexp=&msig=` 导致 401 —— 统一走 `features/media/media-api.ts:mediaReadURL`。

### 12. `/v1/images/edits` 只接受 `image.url`，且地址由上游抓取 ⚠️

传 `file_id` 会得到 `unsupported_parameter`（`transport/http/inference/handler.go:619-621`）。
而该 URL 是 **上游（xAI）去抓**的：本地 `127.0.0.1` 地址上游拿不到，本地联调要用公网图 URL；
本地图片必须先上传到临时输入区（`/v1/media/inputs/upload` 会返回带签名的公开地址），再把该地址作为图编输入。

### 13. `/v1/models` 已新增 `capability` 字段

前端按能力分组（聊天/图片/图编/视频）依赖它；`provider` 仍不外露（不回显上游渠道）。

### 14. 视频能力受账号层级限制（不是路由问题）

视频路由 `id=9 Web/grok-imagine-video` 存在且启用，但 52 个 Web 账号 `tier` 全是 `basic`，
调度返回 `503 upstream_model_unavailable`；带图输入还会被 Web 适配器拒绝（仅支持文本生视频）。
要开通视频需补充支持视频的账号层级，届时才值得恢复 `VideoPanel` 的图生视频/编辑/延长入口。

### 15. 验证「匿名可用」必须先真登出

SPA 会恢复既有管理员会话：只清 `localStorage` 不够（还有 HttpOnly 刷新 Cookie）。
验证脚本需要先调登出接口、再清存储，否则会把「有会话」误判成「匿名可用」。

### 16. 本地纯 HTTP 跑站点时 `auth.secureCookies` 必须为 `false` ⚠️

本机 `server.listen` 是 `127.0.0.1:8000`（纯 HTTP），但 `auth.secureCookies` 原为 `true`；
后端取值逻辑是 `secure := secureCookies || c.Request.TLS != nil`
（`backend/internal/transport/http/adminauth/handler.go:181` 与 `:188`），于是**本地 HTTP 也会下发带 `Secure` 的会话 Cookie**。

Chrome/Edge 对回环地址放行 Secure Cookie，所以**本机 Chrome 看不出问题**；但 Safari、旧内核，以及经主机名/局域网地址
访问时会被浏览器直接丢弃 —— 现象就是「登录看似成功、一刷新就掉回登录页」。

**2026-09-13 已把本地 `config.yaml` 改为 `false`**（备份在 `data/backup-config-20260913/`）；
`config.example.yaml` 与公网部署必须保持 `true`。

### 17. 本机 shell 引号坑（写脚本前务必知道）⚠️

本机命令默认经 PowerShell 执行，**外层会吞掉内层双引号**：`foreach($x in $u)` 会变成 `foreach( in )`，
JSON 请求体的引号丢失后会得到 `400 invalidRequest` —— 看起来像接口故障，其实只是引号被吃掉。

做法：复杂脚本写成 `.ps1` 文件再执行；简单请求用 `curl.exe --data-raw '<json>'` 单引号形式。
另外 PowerShell 5.1 里 `&` 不能作命令分隔符（改用 `;`），`dir /b` 要写成 `cmd /c "dir /b ..."`。

原文档写「52 个 Web 账号至少需要 **7–9 个可用的 Web 出口节点**」。实测结论是**不需要**：
Resin 是**账号级粘性**（`{account}` → 账号 `EgressIdentity`，Web 账号为 `sso_<sha256(token)[:32]>`），

52 个账号 ≈ **1.9 账号每 IP**，优于「每 IP 6–8 账号」的经验值上限。

## 记录的坑

1. **API access cookie 的 path 收敛在 `/api/admin/v1`，整页请求 `/story/` 带不上它**：第一版门禁只读 API cookie，登录态访问也被弹回登录页。解决：新增 path=`/` 的 page-session cookie（同值 access JWT，登录/刷新时同发、登出时同清），门禁按 Bearer → API cookie → page-session cookie 顺序取凭据。代价：access JWT 的 cookie 暴露面从 `/api/admin/v1` 扩到同源 `/`；本站同源只有本站，可接受。
2. **pnpm 在 Windows 上间歇触发 libuv 断言**（`UV_HANDLE_CLOSING`，exit 3221226505）：博客构建改用 `node node_modules/astro/astro.js build` 直跑，结果一致。
3. **Astro 5 legacy（自动生成）collection 的渲染 API**：`entry.body` 是原始 markdown 字符串；渲染要用 `entry.render()` 返回 `{ Content }`（组件，非字符串）；`astro:content` 的 `render()` 函数对 legacy entry 返回空 content。
4. **手动重启服务的正确姿势**：必须先杀旧进程，且注入 `GROK2API_QUALITY_GUARD_DIR`（缺它时进程不报错、不绑端口、无 `server_started` 日志，表现为「启动后 healthz 永远 000」）。用 `scripts/local/start-local.ps1`。

## 六、本轮新踩的坑

1. **`/v1/images/edits` 只接受 `image.url`**：传 `file_id` 会得到 `unsupported_parameter`，
   而且该 URL 是**上游去抓**的 —— 所以本地图片必须先落到临时输入区、再把返回的**签名绝对地址**传进去；
   本地 127.0.0.1 的地址上游抓不到（本地联调要用公网图 URL）。
2. **`/v1/models` 原本不返回 `capability`**（`json:"-"`）：前端想按能力分组必须先把它暴露出来，否则只能退回管理端接口。
3. **视频受账号层级限制**：路由存在 ≠ 能调度，`basic` 层 Web 账号无法出视频（详见第四节）。
4. **匿名验证要先真登出**：SPA 会恢复既有管理员会话，只清 `localStorage` 不够（还有 HttpOnly 刷新 Cookie），
   验证脚本需要先调登出接口再清存储，否则会把「有会话」误判成「匿名可用」。
5. **`next build`/`tsc` 的未使用检查会连环报错**：删组件时要把「类型别名、辅助函数、图标导入、i18n 键」一并清掉，
   否则 `TS6133` 会逐个冒出来。

## 三、P3 · 作品归属与读取鉴权 ✅（本轮核心）

### 3.1 设计决策：为什么最终用「短期签名 URL」

需求是「各看各的」+「作品读取要有鉴权」。三条可行路线与取舍：

| 方案 | 问题 |
|---|---|
| 只认管理员会话 Cookie | ❌ 实测失效：管理员 access Cookie 的 **path 被收敛在 `/api/admin/v1`**（`adminsession/cookies.go`），浏览器同源 `<img>/<video>` 不会携带它 → 管理端图库全部 401 |
| 把管理员 Cookie 的 path 放宽到 `/` | ❌ 会削弱既有安全收敛，且仍解决不了受邀用户（只有客户端密钥、没有管理员会话） |
| 客户端密钥走请求头 | ❌ `<img>/<video>` **无法自定义请求头**，受邀用户在浏览器里看不到自己的作品 |
| **短期签名 URL**（采用） | ✅ 按「作品 + 过期时间」HMAC 签名，把凭证放进 URL；不放宽 Cookie 作用域；`<img>`/`<video>` 直接可用（视频 Range 请求同样可用） |

签名密钥由 `secrets.jwtSecret` 域分隔派生（`HMAC(secret, "grok2api/media-read/v1")`），默认有效期 24h，硬上限 7 天。

### 3.2 数据层

- `domain/media/asset.go`：`Asset` 增 `ClientKeyID uint64`（0 = 未归属的历史数据）。
- `infra/persistence/relational/models.go`：`mediaAssetModel` 增 `ClientKeyID`（`not null;default:0`，**刻意不加外键** —— 历史行取值为 0，且客户端密钥是可删除的配置数据）。
- `schema.go`：`schemaIndexes` 增 `idx_media_assets_client_created ON media_assets(client_key_id, created_at DESC, id)`；列由 `AutoMigrate` 自动补齐。
- `repository/media.go`：`MediaAssetListQuery` 增 `ClientKeyID`（0 = 不限，管理员视图）。

### 3.3 写入归属：走 context，不改存储接口

- 新增 `domain/media/owner.go`：`WithClientKeyID(ctx, id)` / `ClientKeyIDFromContext(ctx)`。
- 注入点：`application/gateway/image.go` 的 `executeImage`、`application/gateway/video.go` 的 `CreateVideo`（两处都能拿到 `key clientkey.Key`）。
- 读取点：`application/media/service.go` 的 `saveImage`、`application/media/upload.go` 的 `commitStagedVideo`。
- 为什么走 context：`provider.ImageAssetStore` 等资产存储接口被多个 adapter 与测试桩实现，扩签名波及过宽；context 只需在网关入口注入一次。

### 3.4 读取鉴权：三条路径

`middleware.MediaReadAuth(admin, clients, signer)`（新增）按顺序尝试：

1. 管理员 access token（Bearer 或会话 Cookie）→ `c.Set(AdminKey, true)`；
2. **有效签名 URL**（`?mexp=&msig=`，`pkg/mediaauth` 校验，恒定时间比较 + 有效期上限）→ `c.Set(MediaSigned, true)`；
3. 客户端密钥（`Authorization: Bearer` / `X-API-Key`）→ `c.Set(ClientKey, key)`。

三者都没有 → 401。`media.Handler.authorizeAsset` 的判定：管理员放行；**有效签名放行**；客户端密钥必须 `asset.ClientKeyID == key.ID` 且 `ClientKeyID != 0`，不匹配一律 **404**（不用 403，避免泄漏他人作品是否存在）。无归属的历史作品仅管理员可读（失败闭合）。

路由拆分（`transport/http/media/handler.go`）：

```
RegisterPublic  → 只保留 PUT /v1/media/uploads/:token（上游回调，票据即授权）
RegisterRead    → GET/HEAD /v1/media/images|videos/:assetId（经 MediaReadAuth）
RegisterClient  → GET /v1/media/images（挂 /v1 组，已受 ClientAuth 保护，只返回本密钥名下作品）
```

### 3.5 签名 URL 的生产与前端配合

- 后端生产：`PublicImageURL` / 新增 `PublicVideoURL` 都改为走 `SignedMediaPath(kind, id)`；管理端视频列表 DTO 增 `url` 字段（带签名）。
- 前端：新增 `media-api.ts:mediaReadURL(url, fallbackPath)` —— 优先用接口返回的 `url`（保留签名 query），同源时退化为相对路径，避免把主机名写死。
  - `gallery-page.tsx`：`<img src>` 改用 `mediaReadURL(image.url, ...)`。
  - `video-gallery-page.tsx`：`<video src>` 改用 `mediaReadURL(job.url, videoAssetURL(job.assetId))`。
  - 创意工坊的 `resolveMediaURL` 本来就保留 `search`，无需改动。

> ⚠️ **后续注意**：任何「用 asset id 自己拼 `/v1/media/...` 路径」的地方都会丢掉签名参数导致 401。新增页面请一律走 `mediaReadURL`。

## 六、本轮新踩的坑（务必记住）

1. **管理员 access Cookie 的 path 是 `/api/admin/v1`**（`transport/http/adminsession/cookies.go`）——浏览器同源 `<img>/<video>` 不带它。给媒体读取加鉴权时**不要**指望这条 Cookie，正确做法是签名 URL（本轮结论）。
2. **前端不要用 id 自己拼媒体路径**：签名在 query 上，自拼会丢签名 → 401。统一走 `mediaReadURL`。
3. **管理接口 `page_size` 有服务端上限**（请求 200 实返 20）：分页必须按响应 `total` 累计，不能按「返回条数 < 请求条数」判断结束。
4. **`POST /api/admin/v1/egress-nodes/{id}/accounts` 的 `ids` 必须是字符串数组**（`[]string`），传整型数组 400。
5. **`POST /api/admin/v1/client-keys` 不回显主键**：创建后要回列表按 name 取 ID（ID 是字符串）。
6. **`curl --noproxy '*'` 会让 `-x` 代理一起失效**（`--noproxy` 是「这些主机绕过代理」）。测代理要先清 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`，再单独用 `-x`。
7. **改 SPA 挂载前缀要同时改三处**：vite `base`、router `basename`、后端静态托管前缀重写；漏一处就白屏或 404。
8. **`PUT /api/admin/v1/settings` 对 providerWeb 的 statsig 字段是无条件覆盖**：不能只提交 media 而省略其它字段，必须先 GET 再整体 PUT（`scripts/set_media_capacity.py` 就是这么做的）。

### 对交接文档的一处修正

原文档第七节 P1 写「52 个 Web 账号至少需要 **7–9 个可用的 Web 出口节点**」。**该表述不准确**：
Resin 是**账号级粘性**（`{account}` 占位符被替换为账号 `EgressIdentity`，Web 账号为 `sso_<sha256(token)[:32]>`），

优于「每 IP 6–8 账号」的经验值上限。**结论：Web 出口节点数不必等于账号数，1 个 Resin 节点即可开跑，分地区池（jp/sg/us）留作后续扩容。**

## 七、部署机选型建议（结论性，供 P7 决策）

**首选：家里常开的 Linux 小主机 / NAS。**

- 与既定方案（单二进制 + systemd + Cloudflare Tunnel）完全对齐，Cloudflare Tunnel 免公网 IP、自动 HTTPS，域名 `ddyu.online` 已托管 CF，可直接接隧道。
- Resin 需与站点**同机常驻**（`socks5h://...@127.0.0.1:2260`），出站走本地代理池；这一条本身就是「不能上 Cloudflare Workers/Pages」的硬约束。
- 需设 systemd `CPUAffinity=`，避免与本地跑模型的进程抢核。
- 唯一新增成本：一台常开机器。

**过渡：当前这台 Windows 电脑。**

- 零新增硬件，可立刻灰度；但无系统服务托管，重启/休眠/网络抖动都会中断站点，且 `GROK2API_QUALITY_GUARD_DIR` 等环境变量需靠计划任务注入。
- 建议只作为 P1/P6 的验证机，不作为长期承载。

**不推荐：纯云服务器 / VPS。**

- 虽然 CF Tunnel 能免公网 IP，但站点价值全在「账号 ↔ 稳定出口」这一基石；Resin 与站点分离部署会徒增链路与故障面。
- 家宽上行带宽才是真实瓶颈（246 个账号流量全部由此上行），机器性能不是关键变量。

**三档共同约束**：

1. `secrets.credentialEncryptionKey` 与 `data/backend.db` 必须**整包迁移**并单独备份，换 key 即 246 账号报废。
2. 迁移前必须先停旧实例（Build refresh token 会轮换，双端并行互相消费）。
3. 媒体容量策略只能走**运行设置**（当前 `maxTotalBytes=1 GiB`、`cleanupThresholdPercent=80` → 到 800 MB 会回收最旧作品），改 config.yaml 无效。
4. P7 的 systemd unit 必须注入 `GROK2API_QUALITY_GUARD_DIR`。
5. 公网部署前：改管理员口令、处理作品 URL 无鉴权（P3）、`trustedProxies` 精确填写、`secureCookies` 保持 true。
