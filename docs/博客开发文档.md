## 一、背景与现状

- 站点形态（开发文档已定）：`ddyu.online` 首页 = 博客，创意工坊在 `/studio`。
- 当前 `/` 是 Go 后端的占位 HTML（`backend/internal/transport/http/frontend.go` 的 `serveLandingPage`），文案「首页施工中，博客将在稍后接入」。
- `static/blog/` 目录已预留（当前为空），后端尚未接线。
- 前端 SPA 由 `frontend.staticPath`（`./frontend/dist`）配置驱动，挂载在 `/studio`，带 SPA 回退。
- 技术栈结论（开发文档第二节，不要推翻）：博客若需 SEO 可**单独**用 Astro 静态站，与 React SPA 并列，同域名不同路径；**不**为迁就博客换掉 React。

## 二、架构决策

| 项 | 决定 | 理由 |
|---|---|---|
| 形态 | **静态博客**（Markdown → 静态 HTML） | 个人博客标准做法；零后端 API，部署即复制文件；与「单二进制 + systemd + CF Tunnel」部署形态完全兼容 |
| 框架 | **Astro**（Node 构建期使用，产物纯静态） | 开发文档已点名；内容集合/frontmatter/RSS 开箱即用 |
| 挂载 | Go 后端把 `static/blog` 挂在 `/`，**替换占位页**；`/studio` 不动 | 复用现有同源托管与 `trustedProxies`/HTTPS 链路，部署零新增组件 |
| 内容位置 | `blog/src/content/blog/*.md`（源码入库） | 文章随仓库走，部署机只拿构建产物 |
| 构建产物 | `astro build` → `static/blog/`（产物 gitignore） | 与 `frontend/dist` 对称；后端 `registerFrontend` 旁边加一个静态挂载即可 |
| 回退策略 | `static/blog` 不存在或无 `index.html` 时，`/` 继续显示占位页 | 博客未构建不影响工坊与站点其它部分 |

**不做的事**（v1 明确排除）：

- 博客不做后端 CRUD、不进 SQLite、不加管理端页面（写文章 = 改 Markdown + 构建）。
- 不做评论（需要后端或第三方服务，v2 再议）。
- 不做全文搜索（v2 可用静态搜索索引，如 Pagefind）。

## 三、站点结构（v1）

| 路径 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | 文章列表（标题/日期/标签/摘要），按日期倒序 |
| `/post/<slug>/` | 文章详情 | Markdown 渲染：代码高亮、图片、TOC |
| `/tag/<name>/` | 标签聚合 | 该标签下文章列表 |
| `/about/` | 关于页 | 站点与作者说明 |
| `/rss.xml` | RSS 订阅 | Astro 内置 RSS 组件 |
| `/404.html` | 404 页 | 后端对未命中路径返回 |

通用能力：深色模式（跟随系统 + 手动切换）、SEO meta（title/description/OG/canonical/JSON-LD）、响应式。

## 六、约定

- 文章 frontmatter 字段：`title`（必填）、`description`、`date`（必填，YYYY-MM-DD）、`tags`（数组）、`draft`（布尔，默认 false）、`cover`（可选，相对 `public/` 路径）。
- 文件名即 slug：`blog/src/content/blog/hello-world.md` → `/post/hello-world/`。
- 写文章流程：改 Markdown → `pnpm --dir blog build` → 刷新浏览器（开发期可用 `astro dev` 热更）。
- 博客代码零后端 API 依赖；如未来需要（评论/搜索），另行立项，不破坏静态形态。
- 域名解耦约束照旧：博客内所有链接用**站内相对路径**，不写死 `ddyu.online`（canonical 例外，构建期注入）。

## 九、踩坑记录（实现中实际遇到并解决）

1. **`post.render()` 返回 Promise**：传统 content collection 的 `post.render()` 需 `await` 后取 `Content` 组件再渲染；直接 `{post.render()}` 会输出空正文。文章页改为 `const { Content } = await post.render()` + `<Content />`。
2. **Shiki 双主题输出模式**：本版本 Astro/Shiki 输出「浅色内联样式 + `--shiki-dark` 变量」，**不**生成 `:root` 变量块。深色覆盖必须用 `.dark .astro-code { background-color: var(--shiki-dark-bg) !important }` 与 `.dark .astro-code span { color: var(--shiki-dark) !important }`（`!important` 用于压过内联样式）。
3. **404 页不能用 `http.ServeFile`**：gin v1.12 中 `http.ServeFile` → `serveContent` 无条件 `WriteHeader(200)`，会覆盖已设置的 404。改用 `os.ReadFile` + `c.Data(404, ...)`。
4. **尾斜杠判断必须在 `path.Clean` 之前**：`path.Clean` 去尾斜杠且合并前导双斜杠，clean 后无法区分 `/post/x` 与 `/post/x/`。先 `strings.HasSuffix(requestPath, "/")` 判断。
5. **Astro 静态资源前缀是 `/_astro/` 不是 `/assets/`**：后端长缓存判断需同时覆盖 `/_astro/` 与 `/assets/`，否则 CSS 被标 `no-cache`。
6. **pnpm 11 构建脚本审批**：`pnpm-workspace.yaml` 需 `allowBuilds: { esbuild: true, sharp: true }`（不是 `onlyBuiltDependencies`），否则 `pnpm install`/`pnpm build` 报 `ERR_PNPM_IGNORED_BUILDS`。
7. **本地起后端需 `GROK2API_QUALITY_GUARD_DIR`**：默认 `QualityGuard.Enabled=true` 且未设该 env 时，`app.New` 里 `qualityguard.Prepare` 返回错误、进程 exit(1)。本地运行须 `export GROK2API_QUALITY_GUARD_DIR=<dir>`。
8. **RSS 域名兜底**：`rss.xml.js` 用 `context.site ?? new URL("/", context.request.url)`，无 `BLOG_SITE` 时回退 dev 地址；生产构建需注入 `BLOG_SITE=https://ddyu.online`。
9. **中文标签 URL**：`/tag/站点/` 浏览器实际发 percent-encoded（`/tag/%E7%AB%99%E7%82%B9/`），后端按 UTF-8 路径匹配正常；curl 直接传原始 UTF-8 字节易被终端搞乱，测试时用编码形式。
